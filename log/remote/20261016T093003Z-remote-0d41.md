T-0001 客户端契约：充值改成「支付宝 / 微信」两个按钮并列

【一句话】下单接口加了一个 channel 字段，老的 type 字段语义不变。
老客户端一个字都不用改；新客户端按下面来。

【1】先问后端开了哪些渠道，别硬编码按钮
      GET https://aikaui.com/api/pay-methods   Header: X-Agent-Key: <现有那把>
      {"methods":[
        {"channel":"alipay","name":"支付宝","provider":"zpay","ready":true,"reason":""},
        {"channel":"wechat","name":"微信","provider":"wechat","ready":true,"reason":""}]}
      ready=false 的按钮置灰，reason 显示在旁边。
      ★ 微信目前还没接通，实际会返回 ready:false —— 这是预期行为，
        界面自动只亮支付宝即可，不需要你们改代码。

【2】下单
      POST https://aikaui.com/api/create-order   Header: X-Agent-Key: <同一把>
      {"user_id":5,"amount":20,"channel":"wechat"}   ← 新写法
      {"user_id":5,"amount":20}                       ← 老写法，仍然能用
      {"user_id":5,"amount":20,"type":"alipay"}       ← 老写法，仍然能用

      channel 取值 alipay / wechat（wxpay、wx、weixin、zfb 也认，大小写不敏感）。
      channel 出现时 type 会被忽略，两个都传只走 channel。

【3】读响应：用新的统一字段，老字段也都保留着
      {"order_no":"AI...",
       "channel":"wechat","provider":"wechat","amount":20,"money":"20.00",
       "payment":{"type":"qrcode",
                  "qrcode":"weixin://wxpay/bizpayurl?pr=xxxx",  ← 画二维码用这个
                  "url":null},                                  ← 非空时给「浏览器打开」
       "code_url":"weixin://wxpay/bizpayurl?pr=xxxx"}           ← 老字段，保留

      支付宝那笔同理，另外还有 pay_url / qrcode / img 这些老字段。
      ★ 渲染二维码只读 payment.qrcode；payment.url 为空就不显示「浏览器打开」。

【4】错误处理
      400 invalid_channel     → 渠道值写错（客户端 bug，不该出现）
      503 channel_unavailable → 该渠道现在用不了 → 自动切到另一个按钮，别弹错给用户
      其余错误码和文案都没变，老代码不用动。
