【余额不足不提示】根因找到了，跟 402 没关系——New API 回的是 403。

一、根因

客户端原来的判定是 `status_code == 402`，可模型通道（New API rc.40）额度不够时回的是

    HTTP 403
    {"error": {"message": "预扣费额度失败, 用户剩余额度: …, 需要预扣费额度: …",
               "type": "new_api_error", "code": "insufficient_user_quota"}}

额度真的 <= 0 时正文是「用户额度不足, 剩余额度: …」，也是同一个 code。
依据是 rc.40 源码 service/billing_session.go 里那个
`types.ErrorCodeInsufficientUserQuota, http.StatusForbidden`。
402 是老的 OpenAI 约定，这条通道上基本见不到，所以钱花光时界面只打一句
「调用模型失败」，用户既不知道是没钱了，也看不到充值入口。

二、改了什么（commit e2d3ef8，分支 local/t-0002-account-code，已推）

- llm.py 加 `insufficient_balance(e)`：先认机器码
  （insufficient_user_quota / insufficient_quota / pre_consume_token_quota_failed /
  quota_exceeded），402 照旧认；403/429 则要求正文里带额度特征串才认。
  **封号、模型没开放这些 403 不会被误判成没钱**——这点是我特意分开的。
- agent_core.run_one_task：余额不足 → 说明白话（「账户余额不足，模型暂时用不了了…」）
  并发 recharge 事件，底部冒出「是否立即充值」；其它错误照旧打原始报错。
- prompts / bus / ui/window 的注释和话术同步改成「402 是老约定，403 是实际」。

三、验证到哪一步（说实话）

- 桩测试全过：上面几种 403/402/500/429 的判定 8 项，run_one_task 确实发 recharge 事件
  且日志不甩原始报错 5 项，bus→offer_recharge(force=True) 及「已经问过一次仍会冒出来」3 项。
- 真实模型调用仍正常（deepseek-flash 回 1 条 choice），没把成功路径改坏。
- **线上没能真复现这个 403**：本地账户余额还剩 ¥0.82，max_tokens 拉到上限也没触发预扣费失败，
  所以 403 这条分支是「按服务端源码 + 桩测试」验的，不是实打实撞出来的。
  等哪天余额真花到 0，麻烦你顺手确认一下界面上有没有冒出那条提示。

四、要你确认一件事

如果 api 代理层（aikaui 这边）自己也包了一层错误、把 New API 的 403 改写成了别的
状态码或别的 code，那我这套判据就会漏。你那边方便的话，回一下
「余额为 0 的账户打一次 chat/completions，实际回的状态码和 error.code 是什么」。
按源码应该是 403 + insufficient_user_quota，但我没实测，不想当成事实写进代码注释里。
