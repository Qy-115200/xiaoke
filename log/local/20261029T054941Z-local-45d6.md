## 背景（2026-10-28 12:14:50 那次 /v1/messages）

客户端看到的 402「余额已用完」，实际是 new-api 的**预扣费估算**失败：
请求体约 997KB（含图片 + 26 个工具定义）+ max_tokens=32000，估算成本超过当时剩余的
¥0.749。用户余额没花光 —— 12:17:50 的下一条就正常通过了，只扣 622 quota（≈¥0.009）。

现在代理把所有额度类 402 都改写成「余额已用完…点这里充值」，会让人**白充钱**。
而且这句话会作为 tool_result 留在 Claude Code 的会话历史里，被反复看到。

## 要求：402 正文改成结构化

HTTP 状态码**保持 402**（客户端和 Claude Code 都按 402 展示，形状别动）。

```json
{"error": {
   "type": "new_api_error",
   "code": "insufficient_user_quota" | "quota_exceeded_for_request",
   "message": "<中文，一句话，给最终用户看>",
   "remaining": 0.749,
   "estimated": 1.21
 }}
```

- `code = "insufficient_user_quota"`：余额真的用完了（remaining ≈ 0）
- `code = "quota_exceeded_for_request"`：余额还在，是**这次请求的预估花费**超过了它
- `remaining` / `estimated` 单位是**元**，不是 quota；拿不到就 `null`
- `message` 里**不要带账户码** —— 这段正文会被抄进截图、日志、会话历史
- 老客户端只认中文正文，所以 message 自己就得说清是哪一种

建议的 message：

- `insufficient_user_quota` → 「账户余额已用完。充值后重试。」
- `quota_exceeded_for_request` → 「这次请求的预估花费超过了剩余余额（还剩 ¥0.75）。
  精简上下文或去掉图片后重试，也可以充值。」

## 请不要做的

- **不要为了让请求通过去截断 max_tokens**：工具调用会停在半个 JSON 上，
  比明确报错难查得多。
- 不要把这个 402 改成 200 + 空回复。
