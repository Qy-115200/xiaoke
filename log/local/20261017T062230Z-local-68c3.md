【可行】余额用完时在终端里给一个可点的充值链接——实测通了，需要你在 402 里带上 OSC 8 序列

一、先纠正我上一条的说法：我之前说"报错文字里嵌链接做不到"，是没实测就下的结论，错了。

我在本机拿 Claude Code 2.1.300 的**交互界面**（真 ConPTY，不是 -p 模式）对着一个假 API 验了两种写法：

1. message 里写裸 URL（aikaui://recharge 和 https://aikaui.com/recharge 都试了）
   → 终端里原样打成文本，**不可点**。Claude Code 的错误行不会自动识别 URL。

2. message 里嵌 OSC 8 超链接
   → Claude Code 把转义序列原样透传到终端，终端渲染成可点链接。
   抓到的实际字节（十六进制形式，避免在这条线上带控制字符）：
     1B 5D 38 3B 69 64 3D 34 77 73 78 62 3B 61 69 6B 61 75 69 3A 2F 2F 72 65 63 68 61 72 67 65 07
     点这里充值
     1B 5D 38 3B 3B 07
   也就是 ESC ] 8 ; id=…;aikaui://recharge BEL 点这里充值 ESC ] 8 ; ; BEL。
   我用 ST（ESC \）结尾发的，Claude Code 自己换成了 BEL 并补了个 id，说明它是解析过再重发的，不是盲目拷贝。

二、这对你那边意味着什么

402 的 message 里直接放这种序列即可。JSON 里就是标准转义：

  {"error": {"message": "余额已用完 \u001b]8;;aikaui://recharge\u001b\\点这里充值\u001b]8;;\u001b\\\n
              也可以在桌面打开「Claude Code 助手」→ 用量信息 → 充值"}}

三个必须：
1. **保持归一成 402**。403 那条路 Claude Code 会按"鉴权失败"处理，加一句
   “Please run /login”，而且它的错误详情做过控制字符清洗，链接会被抹掉。
   你现在的代理把额度错误改写成 402，正好落在无特殊处理的通用分支上。
2. **确认你那层没有清洗控制字符**。如果 token-service 在写响应前会 strip
   \x00-\x1f（有些日志/安全中间件会），链接就没了。建议加一条自测：
   实际请求一次余额为 0 的账户，把响应 body 按字节 dump，确认 1B 和 07 还在。
3. **把账户码从 message 里拿掉**。现在 402 正文带账户码明文，它会留在终端的
   回滚缓冲和 Claude Code 的会话记录里。客户端自己 identity.json 里有码，
   充值不需要你传；换设备登录也不该靠余额报错来泄露。

三、客户端这边已经做完了（commit d91c620，分支 local/t-0002-account-code）

- 安装助手启动时一直会注册 aikaui:// 协议（HKCU，指向 exe 自己）。
- 新增「只办充值」启动方式：被 aikaui://recharge 唤起时，不建托盘、不起 Agent、
  主窗口隐藏，只弹充值窗；关掉充值窗直接退出，不留常驻进程。
- 顺手处理了 Windows 常给链接末尾加斜杠的问题（aikaui://recharge/）。

你那边把 OSC 8 加进 402 之后，整条路就是：余额用完 → Claude Code 打出
「API Error: 402 余额已用完 [点这里充值]」→ 点一下 → 本地助手弹出充值窗。

四、两个边界，先说清楚

- 终端要支持 OSC 8。Windows Terminal、新版 VS Code 终端支持；老的 conhost
  可能只显示文字。建议保留一句纯文字兜底（比如"也可以在桌面打开助手充值"）。
- 这是 2.1.300 的行为。以后 Claude Code 升级有可能改成清洗错误文本，
  升级后要重验一次。客户端侧只能保证链接目标（协议 + 充值窗）一直有效。
