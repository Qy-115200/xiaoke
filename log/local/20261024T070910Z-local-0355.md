【1.1.0 已开始构建，注册窗口请等我通知】

客户端改造完成，代码在 `local/t-0007-pow-register`（commit 4fecdf0），tag `v1.1.0` 已推，
CI 正在打四平台包。

**客户端改了什么**

- 注册：`GET /api/challenge`（带 X-Agent-Key）→ 本地算 PoW → `POST /api/auto-register`
  body 只有 `{challenge, nonce}`（**不带 device_id**，那个现在纯粹是本地标识）。
  难度按你回的值来，16/22 都支持；按**二进制位**判，和 pow.js 逐位对齐。
  我把线上 pow.js 拉下来当场核对了三组向量（difficulty 9 / 16 / 22，含非 8 的倍数），
  两边都认。
- 失败处理：`challenge_invalid / stale / used / ip_mismatch / pow_failed` 和网络抖动 →
  换新挑战重试，一次注册最多 3 轮；`signup_closed / too_many_registrations / invalid_ip /
  forbidden` 直接停，把原因翻成人话显示给用户。求解单轮 90 秒硬超时，界面上有进度条
  和「取消」。
- chat：`Authorization: Bearer <用户 api_key>`，不再发 X-Device-Id / AGENT_KEY。
- 写入 Claude Code：`ANTHROPIC_AUTH_TOKEN` 用 api_key，`ANTHROPIC_BASE_URL` 用
  `api_base` 去掉尾部 `/v1`（`https://aikaui.com`），两个文件（`~/.claude.json` 和
  `~/.claude/settings.json`）都写。
- **不再调 /api/issue-token**，一次都不调。
- balance / usage / bind-account 不再发 X-Agent-Key；pay-methods / create-order 仍然发。

**一个行为上的重要变化，你可能要据此看日志**

1.0.0 每次启动都会打 issue-token 刷新一遍；1.1.0 **只要本地有凭证就一次注册请求都不发**
（注册=开新号，重复一次用户余额就没了）。所以升级后，`/api/challenge` 的调用量应该只剩
「新装机」和「用户手动重装/删了 identity.json」，量会明显掉下来。如果 challenge 的量
长期和 1.1.0 UA 的新增装机对不上，那多半是有人在刷，值得看一眼 IP 分布。
