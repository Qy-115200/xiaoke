【终端里还是裸 403：Anthropic 入口 /v1/messages 没走额度归一化】

今天 15:20、15:21 用户在 Claude Code 终端里实测，走的是 identity.json 里
api_base = https://aikaui.com/v1（Claude Code 会拼成 /v1/messages），拿到的是：

  Failed to authenticate. API Error: 403 预扣费额度失败, 用户剩余额度: ＄0.004916, 需要预扣费额度: ＄0.012724
  Please run /login · API Error: 403 预扣费额度失败, 用户剩余额度: ＄0.001266, 需要预扣费额度: ＄0.004194

也就是说：客户端 App 自己那条 /api/chat/completions 的 402 归一化是生效的
（App 里会弹「是否立即充值」），但 Claude Code 走的 /v1/messages 仍把上游 403
原样透传，终端里既没有中文解释，也没有可点的充值链接。用户现在的感受就是
「余额不足显示的问题还没解决」。

需要你在代理层补的：

1. /v1/messages（Anthropic 入口）也识别额度错误。上游 code 可能是
   insufficient_user_quota / pre_consume_token_quota_failed，也可能 code 为空、
   只有正文「预扣费额度失败」/「用户额度不足」/「余额已用完」。命中这些的
   403 都不能原样透传。

2. 命中后统一回 **402**，正文给一句中文说明，并带上 OSC 8 链接：

   \x1b]8;;aikaui://recharge?user_id=<该请求的 user_id>\x1b\\点这里充值\x1b]8;;\x1b\\

   （Claude Code 的终端会透传 OSC 8，裸 URL 点不了；这一点 68c3 里已经实测过。）

3. 正文里不要带账户码明文（会进终端历史/截图）。user_id 可以带，它是链接参数。

客户端这边已经把 403 的兜底判定补到「预扣费额度失败」（llm.py 的
INSUFFICIENT_TEXTS），App 自己的对话不受影响；终端这条只能靠代理。

部署后麻烦回一条：贴一下 /v1/messages 在额度不足时实际返回的状态码和正文
（账户码请打码），我这边好核对 OSC 8 序列有没有被中间层洗掉。
