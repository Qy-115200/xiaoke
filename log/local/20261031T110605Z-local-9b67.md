## v1.5.5 已经上线（2026-10-31 19:05 本地时间）

四个平台都传了 nginx + COS，两边 HEAD 验过大小、sha256 本地先对过，
latest.json 已原子替换，install.sh 从清单取版本（按设计不钉死）。

### 这版改了什么（Windows 的 winget 那条路）

**1. 查清了"winget 装不上"的真正原因。**
用户机器上 `Get-AppxPackage Microsoft.DesktopAppInstaller` 是能查到的，
但版本是 **1.0.30251.0** —— winget 从 1.11 才打包进 App Installer，所以那个包里
根本没有 `winget.exe`，`winget` 不在 PATH 里是**正确现象**，不是环境坏了。
我们想用 1.11.430 原地升级它，`Add-AppxPackage` 在部署阶段 `IOException` 失败
（1.0 是系统预置包，用户态原地升级经常卡在这）。
现在装不上会把版本说出来并提示去 Microsoft Store 更新，不再只写一句"装不上"。

**2. `find_winget()` 不再猜路径。** 顺序改成 PATH → 执行别名 →
最后问一次 `(Get-AppxPackage Microsoft.DesktopAppInstaller).InstallLocation`。
以前 PATH 第一条 WindowsApps 可能属于别的账户（空壳别名 → WinError 3），
`%USERPROFILE%` 也可能和真实 profile 目录不是一个。

**3. 便携版彻底删掉。** 解压出来的 winget 没注册成 AppX 包，源索引永远打不开，
装任何东西必然 `0x8A15004B`。以前还会解压一份、打"已装好 winget（便携版）"、
下一句又说"读不到软件源"。

**4. 240MB 官方安装包改成 6 路分段下。** 先问 `update.code.visualstudio.com`
的 update API 拿带版本号的真实地址 + `sha256hash`，再用 Range 切 6 段并发。
本机实测 251,590,472 字节 / 90.9 秒 / 2.64MB/s（单连接是 ~450KB/s，9 分钟），
sha256 对得上、分片清干净。分段不成会退回单连接，退回后**仍然验 sha256**。
用户点中断不会偷偷再下一遍。

### 对远端的影响

只有 `platform_support/windows.py` 和 README 变了，接口签名没动
（`find_winget` / `ensure_winget` / `install_vscode` 都还是原来那套；
`ensure_winget` 的 `mode` 少了 `portable` 这个取值，我们内部没有消费方）。
`server_main.py`、协作脚本一个字节都没改。测试 779 → 806 全绿。

分支 `local/t-0004-winget`，tag `v1.5.5`，CI 5/5 绿。
