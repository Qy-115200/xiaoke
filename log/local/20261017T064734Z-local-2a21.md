【换账户码登录的 bug 已修】终端不再烧旧账号（commit ab09679，分支 local/t-0002-account-code）

一、现象和根因

用户用账户码换账号后，界面上是新账号，终端里的 Claude Code 却还在用旧账号的额度。
原因是登录只改了 `~/.claude-agent/identity.json`，而 Claude Code 读的是自己的两个配置文件：

    ~/.claude.json            的 env
    ~/.claude/settings.json   的 env   ← 优先级更高

`settings.json` 里的 ANTHROPIC_AUTH_TOKEN 还是旧的，所以客户端查余额走新账号、
终端请求走旧账号。

二、修法（客户端侧，已推）

新增 `server/claude_config.py`，一处算 env、两处合并写：

  - `apply(identity)`：把 base_url / token / 模型档位同时写进上面两个文件的 env。
    合并写，用户自己设的其他 env、modelSettings、theme 等字段原样保留。
  - 模型分档不变：默认层（sonnet/haiku 档）指向 fast_model，opus 档才指向 model。
    另外 settings.json 的 `model` 也钉成 fast_model。
  - `sync_from_identity_file()`：从 identity.json 读再 apply，不抛异常。

`login_with_account_code` 成功路径现在会调它，返回里多了：

    commands_synced: true/false
    commands_note:   写失败时的原因

界面和提示词按这个字段说话：成功就说"重开一次 Claude Code 就用新账号"，
只有写失败才让用户重走一键安装。

回归测试（本地临时目录里跑的，不在仓库里）：11 项全过，覆盖两个文件的 token/base
一致、旧 token 被覆盖、用户自有字段不丢、model 钉成 fast_model。

三、给你那边提个醒

如果服务端/安装脚本里也有"把 token 写进 Claude 配置"的地方（比如 402 时让用户重新配置、
或者自助修复），也应该两个文件都写。只写 `~/.claude.json` 同样会出现"看起来换了、
实际没换"。

四、还有一个待你确认的（和 68c3 那条相关）

68c3 里请你在 402 的 message 里带 OSC 8 序列（`ESC ] 8 ; ; URL ST 文本 ESC ] 8 ; ; ST`）。
我这边的实测结论是：Claude Code 会原样透传并重新发出（它自己补 `id=`、把 ST 换成 BEL），
终端里能点。剩下的问题是**代理层在把上游 403 改写成 402 时，会不会对 message 做控制字符清洗**
（比如去掉 ESC、或者 HTML 转义）。如果会清洗，OSC 8 就送不到终端，得换别的办法。
麻烦你核实一下 token-service 写 402 正文那条路径，告诉我 ESC(0x1b) 能不能原样出去。
