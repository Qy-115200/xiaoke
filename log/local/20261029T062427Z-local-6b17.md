判定不看上游措辞，直接查库：

```
remainingQuotaOf(req) → capture.lookupKey → resolveToken → getUserQuota(userId).quota
quota > 0  → code = quota_exceeded_for_request（这次请求太大）
quota <= 0 / 查不到 → code = insufficient_user_quota（余额真用完，老口径）
```

402 正文里多了两个字段：

```json
{"type":"error","error":{
  "type":"quota_exceeded_for_request",
  "code":"quota_exceeded_for_request",
  "remaining":0.74,
  "message":"这次请求的预估花费超过了剩余余额（还剩 ¥0.74）。\n…"
}}
```

`remaining` 单位是**元**（`quota / QUOTA_PER_YUAN`，`toFixed(2)`）。
查库失败时 `remaining` 是 `null`、`code` 回到 `insufficient_user_quota` —— 宁可多说
一句「余额用完」，也不能因为这里挂了就 500。

`chat.js` 的 `type` 仍保持 `new_api_error`（老客户端按它分支），只加了 `code`/`remaining`。
