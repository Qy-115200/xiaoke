# 两个 Agent 的协作接口（PROTOCOL）

这份文件是**接口**本身：规约文件长什么样、命令怎么调、出了分歧按哪条判。
参考实现是同目录的 [collab.py](collab.py)，两边跑的必须是同一份。

一句话概括：**拿一个 git 分支当总线——对话是消息文件，任务是任务文件，git 的推拉就是同步和加锁。**

---

## 0. 三张图

### 全景：谁跟谁说话

```
   人                          人                    ← 人跟两边各说各的
   │ 说话                     │ 说话
   ▼                          ▼
┌─ 本机 local ─────────┐  ┌─ 远端 remote ────────┐
│ Claude Code 会话 ✗   │  │ Claude Code 会话 ✗   │   ✗ = 本地·临时
│ 代码工作区           │  │ 代码工作区           │       会话关了就没了
│ 协作镜像             │  │ 协作镜像             │       两边互相看不见
└──────────┬───────────┘  └──────────┬───────────┘
           │                         │
        推 ▼                      推 ▼          ← 只写自己的格子
   ╔═════════════════════════════════════════════╗
   ║  git 远端 —— 唯一的共享物、唯一的真相        ║
   ║                                             ║
   ║  collab 分支（孤儿分支）  对话 + 任务         ║
   ║    log/local/*.md      ← 只增不改，各写一格   ║
   ║    log/remote/*.md                          ║
   ║    tasks/T-0001-local.md                    ║
   ║                                             ║
   ║  local/t-0001-…   ┐                         ║
   ║  remote/t-0002-…  ├─ 代码分支                ║
   ║  main  ───────────┘    ↑ 只有人合            ║
   ╚═════════════════════════════════════════════╝
```

**两台机器之间没有任何直连**。所有信息都绕一圈走 git 远端——包括"我刚才说了句话"。
这不是绕远，是因为：直连要两边同时在线、要打通网络、要处理谁先谁后；
走 git 这些全都由 git 自己解决了。

### 时间线：一次协作长什么样

```
时间 ⏷
        local                            remote
          │                                │
 人:「修余额显示」                            │
          ├─ task new T-0001 ──▶[git]──▶    │
          │                                │
          │                        人:「我来」
          │  ◀──[git]◀── claim T-0001 ─────┤   → owner = remote
          │                                │
          │  ◀──[git]◀── ask「403 是不 ─────┤
          │                是也走充值？」    │
          ├─ answer「要」───▶[git]──▶        │
          │                                │
          │                        改代码 → push 自己的分支
          │  ◀──[git]◀── done T-0001 ──────┤
          ▼                                ▼
```

注意 `task` / `claim` / `ask` / `answer` / `done` **全是消息**，没有一个是"改某个状态字段"。
这就是第 1 节说"状态是算出来的"的意思——把它们按时间一排，当前状态就有了。

### 抢任务：唯一需要点聪明的地方

```
两边几乎同时认领同一个任务：

  local  : claim ──push──▶ ✓ 服务端接受（先推上去的赢）
  remote : claim ──push──▶ ✗ 被拒（non-fast-forward）
                             │
                             ├─ fetch + rebase：把自己那条叠到新顶端
                             ├─ 复查 T-0001：owner 已经是 local，而且比我早
                             └─ 删掉自己那条 claim → 再 push  ✓
                                （别人看到的不是我抢输的痕迹，
                                  而是压根没抢过）

  结果：local 拿到任务，remote 干净退出。
  全程没有人介入、没有锁、没有等待、两边也不需要先商量谁先谁后。
```

第 5 节会把这三个情形（同时认领 / 同时开号 / 离线）逐个说清楚。

## 1. 三条不变量

整套东西能成立，全靠这三条。加功能时可以改别的，这三条不能动。

| # | 不变量 | 为什么 |
|---|---|---|
| 1 | **只增不改。** 一条消息 = 一个新文件；推上去之后谁都不许再改它 | 两个 Agent 永远不碰同一个文件，git 合并在结构上就不可能有冲突 |
| 2 | **状态是算出来的。** 任务归谁、做没做完，都由流水现算，没有任何"当前状态"文件 | 一旦有共享可写文件，就得引入锁、租约、超时回收——全是不必要的复杂度 |
| 3 | **`git push` 就是那把锁。** 服务端对同一个 ref 只接受一次更新，"谁先推上去"天然互斥 | 不用锁服务、不用常驻进程、两边也不用先商量谁先谁后 |

由此推出来的两条副作用，都是故意的：

- **没有"在线"要求**。推不上去就先记在本地，挂在账上，`sync` 时补推。
- **没有中心节点**。两边对等，谁宕机都不影响另一个继续干（只是看不到新消息）。

## 2. 仓库与分支

> ⚠ **开工前先把仓库可见性确认掉。** `Qy-115200/agent_demo` 现在是 **public**——
> 匿名 `git ls-remote` 就拉得到。协作分支一旦推上去，两边说的每一句话、开的每一个任务
> **全世界都能看到**，而且会永久留在 GitHub 的历史（以及各家 fork / 镜像）里，删不掉。
> 二选一：
> - 把仓库改成 private（Settings → General → 最下面的 Danger Zone → Change visibility）；
> - 或者另建一个**私有**仓库专门放协作数据：`init --repo <私有仓库地址>`，见第 12 节。
>
> 私有仓库要两台机器各有写权限（PAT 或部署密钥）——**这个东西由人各自放上去，不要经过聊天记录**。

| 用途 | 位置 | 谁写 |
|---|---|---|
| 协作数据（对话 + 任务） | 分支 `collab`，**孤儿分支**（没有共同祖先，跟代码历史完全不相干） | 两个 Agent 都写，各写各的文件 |
| 代码 | 各自的分支 `<agent>/<task-id>-<短描述>` | 谁认领的任务谁写 |
| `main` | 发布线 | **只有人合**。Agent 任何情况下都不直接推 `main` |

为什么数据要单独放一个孤儿分支：

- 代码历史里不会混进几百条"说了句话"的提交；
- 协作分支的克隆只拉这一个分支，很轻；
- 两边在代码分支上处于什么状态（脏工作区、detached HEAD、随便什么）都不影响协作。

协作分支上的目录（由 `collab.py init` 建好）：

```
(collab 分支根)
├── .gitattributes      * -text —— 关掉换行转换，Windows 写的 LF 不会被改
├── cfg.json            两个 Agent 的名字 + 地盘划分（唯一需要人手工改的文件）
├── README.md           给误入的人看的：这里不放代码
├── log/<agent>/        发言。每人只写自己那一格，一个文件一条
│   └── 20261016T071435Z-remote-7ba7.md
└── tasks/              任务说明。文件名带作者，防止两边同一秒开同一个号时路径相撞
    └── T-0001-local.md
```

> **协作数据不放代码、不放密钥、不放二进制。** 这个分支两边都能看到，
> 而且会在 git 历史里永远留着——写进去就撤不回来了。

## 3. 消息格式

一个文件一条消息。头部用 `---` 包起来，其余全是正文（Markdown）。
**故意不用 YAML**：解析器就十几行，不引入依赖，也不会有人写出嵌套结构。

```markdown
---
id: 20261016T071435Z-remote-7ba7
from: remote
to: local
kind: ask
re: T-0001
area: server/
subject: 要不要顺手把 403 也当成余额不足处理？
at: 2026-10-16T07:14:35Z
---

正文。可以写多段、贴 diff、贴报错。
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✔ | 全局唯一。格式 `<UTC时间戳>-<作者>-<4位随机>`，**同时就是文件名**（`log/<作者>/<id>.md`） |
| `from` | ✔ | 作者，等于所在的 `log/<agent>/` 目录名 |
| `to` | ✔ | 对方的名字，或 `all` |
| `kind` | ✔ | 见下表 |
| `re` | | 挂在哪个任务（`T-0001`）或哪条消息（完整 id）上。可为空 |
| `area` | | 涉及哪块代码（`ui/`、`server/`…），只用来提示地盘，不强制 |
| `subject` | | 一句话标题。任务消息里它就是任务标题 |
| `at` | ✔ | UTC ISO 时间。**只用于排序**，不用它算时间差 |

### 消息类型

| kind | 意思 | 状态影响 |
|---|---|---|
| `task` | 开一个任务（文件在 `tasks/`，不在 `log/`） | 新任务诞生 |
| `claim` | 我要做这个任务 | 该任务 owner = 我（如果我是最早的） |
| `release` | 我不做了，放回公池 | owner 清空 |
| `done` | 做完了 | 任务标记完成 |
| `cancel` | 这个任务不做了 | 任务标记取消 |
| `ask` | 提问，**并且我在等答复** | 对方 `status` 里会出现"待我回复" |
| `answer` | 答复某条 `ask`（`re` 指向被答复的那条） | 提问从待办里消失 |
| `note` | 说一句，不需要谁回应 | 无 |
| `handoff` | 我要下线/换人，把活交给你 | 无（交接内容写在正文里） |

`ask` / `answer` 是唯一一对有"未结清"概念的：**收到 `ask` 就必须 `answer`**，
哪怕答案是"不知道"或"这个我不该动"。别的类型不回也没关系。

## 4. 任务怎么流转

没有"状态字段"，状态是从流水算出来的：

```
        task 消息诞生
              │
              ▼
          ┌─────────┐   有人 claim    ┌─────────┐   done   ┌─────────┐
          │ 待认领   │ ─────────────▶ │ 进行中   │ ───────▶ │ 已完成   │
          └─────────┘                 └─────────┘           └─────────┘
              ▲                            │
              └────────── release ─────────┘
```

判定规则（两边算出来必须完全一致，所以规矩写死）：

1. **owner = 最早那条 `claim` 的 `from`。** 要撤销某人的 owner，只有 `release` 或它自己的 `done`。
2. **谁最早，按 `(at, from, id)` 三元组比大小。** 时钟撞在同一秒时用作者名兜底，名字也一样时用随机 id——
   所以两边算出的结果必然相同。
3. 已取消（`cancel`）的任务不能再 claim；已完成的不能再 claim。
4. `release` / `done` / `cancel` 只能由 owner 自己发。

**两台机器的时钟不需要精确同步**，差几分钟完全无所谓；只有差到几小时才可能判错先后。
真想彻底稳，可以两台都开 NTP——但正常不需要。

## 5. 并发：三个必须处理的情形

**① 两边同时认领同一个任务。**
两个人都写了 claim、都提交了，但只有一个 `push` 能成功。推成功的一方在拉取后复查：
如果发现有比自己更早的 claim，就**自己把自己那条删掉**、再推一次。所以不需要谁先报名、
也不需要冲突之后有人来仲裁——**输的那方自动退出**。

**② 两边同一秒开同一个任务号。**
任务文件名带作者名（`T-0001-local.md` / `T-0001-remote.md`），路径不撞，git 不冲突。
谁算数按第 4 节第 2 条定，输的那份被忽略；`collab.py status` 会把被忽略的那份列出来提醒删掉。

**③ 离线（没网 / 没权限 / 远端正忙）。**
本地先提交，`collab.py` 会明确告诉你"已本地记账，但还没生效"。联网后 `sync` 补推；
补推时如果发现自己其实抢输了，一样自动撤回。**离线期间不要以为认领已经算数。**

## 6. 命令一览

两边跑的是同一个文件：代码分支里的 `collab/collab.py`。只用标准库，Python 3.8+。

```bash
python3 collab/collab.py init --as <我的名字> [--repo <git 地址>]   # 一次性
python3 collab/collab.py status [--json|--all]                     # 每次开工先看
python3 collab/collab.py poll                                      # 只看新消息
python3 collab/collab.py sync                                      # 拉取 + 补推
python3 collab/collab.py task new --title "…" [--area ui/] [-m 正文]
python3 collab/collab.py claim|release|cancel|done <T-0001> [-m 说明]
python3 collab/collab.py send --to <对方> [-m 正文] [--re T-0001]
python3 collab/collab.py ask  --to <对方> -m "…"      # 等答复
python3 collab/collab.py answer <短句柄|id> -m "…"    # 答复
python3 collab/collab.py handoff --to <对方> -m "…"   # 交接
python3 collab/collab.py log [-n 20] [--kind ask] [-v]
python3 collab/collab.py show <id>                     # 某条消息/任务全文
python3 collab/collab.py digest                        # 几行态势（给 hook 用的）
python3 collab/collab.py hooks [--write]               # 装/看"自动查 git"的 hook
python3 collab/collab.py notify [--set URL --secret K|--test|--clear]   # 可选快路，见第 9 节
python3 collab/collab.py export [--out 文件]           # 导出人看的完整记录
```

`claim` / `done` 这类命令里的"我的名字"来自 `--as`、环境变量 `COLLAB_AGENT`，
或 `init` 时存下的 `~/.claude-collab/self.json`。

**环境变量**

| 变量 | 作用 |
|---|---|
| `COLLAB_AGENT` | 我是谁（`local` / `remote` / …） |
| `COLLAB_HOME` | 镜像仓库和本地游标放哪。默认 `~/.claude-collab`。一台机器一个身份，同机要跑两个身份就设两个值 |
| `COLLAB_NOTIFY_URL` / `COLLAB_NOTIFY_SECRET` | 第 9 节那条可选快路。不设就纯走 git，功能一样，只是慢一点 |

**退出码**：`0` 成功；`1` 抢任务输了（正常情况，不是错误）；`2` 用法/环境问题（没 init、连不上、id 找不到）。

## 7. 代码怎么协作

协作分支只管协调，**代码走 git 原本那套**。

| 规矩 | 说明 |
|---|---|
| 分支命名 | `<agent>/<task-id>-<短描述>`，例如 `remote/t-0001-balance-403` |
| 一个任务一个分支 | 别在一个分支上混两件事，不然对端 review 不动 |
| 不推 `main` | Agent 只推自己的分支；`main` 由人合（或人当面授权后由一个 Agent 合） |
| 跨分支不要互合 | 协作分支不要 merge 进代码分支，也不要反过来 |
| 动手前看地盘 | `cfg.json` 的 `areas` 是建议分工。要动别人地盘，先 `ask` 一句，别默默改 |
| 有争议看 diff | 意见不合就贴 diff 到 `log/` 里说，别在代码分支上互相覆盖 |

`cfg.json` 里的默认分工（人随时可以改，改完直接提交到协作分支）：

```json
"areas": { "ui/": "local", "main.py": "local", "config.py": "local",
           "server/": "remote", "prompts.py": "remote" }
```

## 8. 让"读"变成自动的（hook）

协作分支只解决"信息存在哪"。**它不解决"谁去看"**——而这才是两个 Agent 协作真正会掉链子的地方。

先说清楚边界：

- **会话上下文是本地的、临时的。** 你这轮记得的东西，对端看不到；会话一关，你自己也没了。
- **git 给的是"共享的外存"，不是"共享的记忆"。** 写进去 ≠ 对方知道，对方必须**读**才知道。
- 所以问题不是"怎么共享记忆"，而是**"怎么让'读'不依赖谁记不记得"**。

`collab.py digest` 就是为这件事写的：几行话说清当前该知道什么，**永远退出 0**，
单次网络硬超时。它的 stdout 会被 hook 原样塞进上下文——**模型一定会看见，不是"希望它记得看"**。

两个事件的分工是有意的：

| 事件 | 频率 | 参数 | 理由 |
|---|---|---|---|
| `SessionStart` | 每次开会话 | `--long --fetch-max-age 0 --timeout 15` | 会话开头肯等，所以强制问一次远端 |
| `UserPromptSubmit` | **每次用户开口** | `--fetch-max-age 180 --timeout 6` | 挂得最密，所以 180 秒才问一次、6 秒硬超时 |

`UserPromptSubmit` 那行是刻意的保守设计：**它的输出会进每一轮的上下文**，
所以输出必须短（几行），网络必须少碰（不然网络一抖，用户每打一句话都卡几秒）。
**永远退出 0** 也是硬要求——hook 非零退出会打断用户，一个观察动作没资格成为故障源。

装（每台机器各跑一次）：

```bash
python3 collab/collab.py hooks            # 预览
python3 collab/collab.py hooks --write    # 写入 .claude/settings.local.json
```

写 `settings.local.json` 而不是 `settings.json` 是刻意的：那行命令含**绝对路径**和
**平台相关的解释器名**（Windows 是 `python`，Linux 普遍是 `python3`；`$VAR` 和 `%VAR%` 又不通用），
提交上去只会让两台机器互相覆盖。所以**共享的是这条命令怎么生成，不是生成出来的那个文件**：

- 跨 `UserPromptSubmit` / `SessionStart` 的那份 **意图**，写在 `CLAUDE.md` 里，随 git 传播；
- **具体那行命令**由各台机器自己 `hooks --write` 生成。

首次写入会被 Claude Code 拦一次要求确认（二进制里那个 `hooksSkippedByTrust`）——
**这是防「克隆个仓库就被执行任意命令」的保护，不要绕开它**。

## 9. 可选的快路：只回一个版本号的通知通道

到第 8 节为止，同步的天花板是 `--fetch-max-age`。对方刚好在你查完之后写了东西，
你最多要等一整个周期才知道。想更近实时，就得有人**主动告诉你"变了"**。

`collab/notify_server.py` 只干这一件事。它**不传消息**，只回答一个问题：

```
GET  /v?ch=default            → {"v": "6af2f55b9688…"}   变了没有，看这个字符串
POST /v?ch=default   Bearer   → 更新版本号（谁推完谁喊一声）
```

于是 `digest` 变成两层：

| 层 | 触发条件 | 作用 |
|---|---|---|
| ① 快路 | 通道说"变了" | 立刻 fetch，不用等 |
| ② 兜底 | 距上次真 fetch 超过 `--backstop` | 不管快路说什么，到点必须真拉一次 |

> **兜底那一层才是这套设计能成立的原因。** 有了它，快路可以是第三方的、可以撒谎、
> 可以随时挂掉、可以被人重放 —— 最坏结果只是同步晚一个兜底周期，**不会错**。
> 所以这条通道"拔掉"是零损失的：`notify --clear` 之后一切退回第 8 节的样子。

三条硬规矩，都是为了**别让它变成一个往模型脑子里写字的入口**：

1. **它回不了自由文本。** 版本号被限死成 `^[0-9A-Za-z._:-]{1,80}$` —— 装不下任何句子。
   `digest` 的 stdout 会被原样塞进上下文，一条能回任意字符串的通道，就是一个提示词注入接口。
   服务端对超长和带中文的输入一律 400，这一条是测过的。
2. **读不要鉴权，写要密钥。** 读到的只是"变没变"，泄露了不值钱；写要密钥，免得有人乱按喇叭。
3. **它挂了不影响协作。** 问不到就退回按 `--fetch-max-age` 的老节奏，`digest` 照样退出 0。

服务端只用标准库，跑起来：

```bash
COLLAB_NOTIFY_SECRET=$(openssl rand -hex 16) python3 notify_server.py --port 8787
```

默认只绑 `127.0.0.1`。**要对外就在前面放 nginx/caddy 收 TLS**，并且只转发 `/v`；
这个服务自己说的是 plain HTTP，别直接对着公网。

两边各配各的（配置存在各自的 `self.json` 里，谁也替不了谁 —— 没配的那边推完不喊）：

```bash
python3 collab/collab.py notify --set https://notify.example.com --secret <密钥>
python3 collab/collab.py notify --test        # 当场喊一声试试
```

也可以用环境变量 `COLLAB_NOTIFY_URL` / `COLLAB_NOTIFY_SECRET`，优先级高于 `self.json`。

## 11. 边界：这套东西不做什么

| 不做 | 原因 |
|---|---|
| 即时通信 | 没有推送、没有守护进程。对方下次跑 `poll` 才会看到。要即时就用 Claude Code 自己的跨会话消息 |
| 传密钥 / token | 协作分支两边可见、且永久留在 git 历史里。密钥只能各自放在自己机器上 |
| 传二进制 / 大文件 | 会让协作分支的每次 clone 都变重。大文件走各自的分支或外部存储 |
| 代替 code review | 这是协调层，不是审议层。代码质量还是靠 diff 和人的判断 |
| 自动合 `main` | 发布线始终由人掌握 |

## 12. 想换一个仓库？

完全支持——协作仓库不必是代码仓库：

```bash
python3 collab/collab.py init --as local --repo https://github.com/<你>/<协作仓库>.git
```

换仓库时 `COLLAB_HOME` 也要跟着换（镜像和身份是按 home 存的），例如
`COLLAB_HOME=~/.claude-collab-x`。两个仓库互不干扰。
